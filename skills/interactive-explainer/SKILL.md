# 交互式讲解页

让读者追踪一个对象，动手改一个条件，解释结果为什么变化。按用户指定的受众、语言、载体与技术栈交付。要求做页面时，产出能实际打开和操作的页面；要求评审或设计时，交付相应范围的结果。

## 找到值得追的问题

- 从读者想弄懂的现象入手。“两次投递为什么只出现一张订单？”比“系统有哪些组件？”更容易决定画什么。选一个普通读者能认出的具体对象，让它的名字、ID、单位或位置贯穿全页。
- 从给定源码、规范、样例或记录追到最终结果。区分实际测量、由规则算出的值、预录回放和结构示意，在相关视图就近说明。材料不足时可以做明确标注的教学模型，写出改变结论的简化假设。
- 设计时先推演一组可以区分两种解释的例子。记下基线、只变动的条件、第一个产生差异的中间状态、最终结果，以及一个应保持稳定的量。两种解释若始终给出相同结果，换一个更能说明机制的输入。

## 在同一幅图里讲清机制

先画出默认案例，后写解释。把首屏最主要的空间留给读者要追踪的对象和它的变化。涉及先后，在时间轴上对齐两次事件；涉及分支，沿路径标出请求去向；涉及矩阵，圈出参与计算的一行和一列。形状、位置、连接或长度应能回答一个具体问题。遮住解释段落，只保留短标签和单位，检查能否从图上指出输入、发生变化的地方和输出。指不出来就重画主图。

- 用空间表达真实结构。串联按先后排布，并行在分支处展开，重复单元显示一个代表和总数。颜色稳定表示角色，并配合形状、线型或直标。线宽、面积等数值编码需要有实际含义。
- 直接在对象上提供展开入口。点击概览中的运算、节点或区间，它在当前位置让出空间，内部阶段从该处出现；相邻对象平移，连线端点跟随。始终留一个上游或下游对象作参照。收回时让细节沿来路归拢，保留原输入、选择和焦点。
- 展开的是能追踪的证据。让读者选中某个输出，看见对应的输入行列、当前公式项或产生它的事件。比较所需的中间结果保留在图上，供目光来回移动。说明文字跟随当前选择，补充图形表达不了的因果理由。
- 初次接触者可以直接看一个带解案例。对象多到可能迷路时，增加可跳过的短导览。每步只聚焦图中的一个动作，点图中部件也能回到同一步解释。

## 让操作检验理解

选一个有实际后果的控制项。让读者随时在同一输入下比较基线和变式，并能恢复基线。离散情景适合切换或回放，连续、有意义的参数适合滑杆。让图、数值、文字和选中对象读取同一个案例状态，修改条件后一起更新。涉及随机性时分别展示概率与单次抽样，需要复现时固定种子或记录样本。

把提问放到结果揭晓前的自然停顿。第一次接触可以直接看带解示例；有基础的读者可以先猜。把预测放在触发该变式的控件旁；切换后将原提问收起或换成当前案例的反馈，复位时恢复提问。揭晓时点亮第一个分岔，给出该对象的前后值和传到下游的理由。若两种条件最终结果相同，也指出中途哪里不同、哪个机制保住了结果。读者可直接看解释；不要把探索锁在测验后面。有迁移价值时，换一个只改变关键条件的案例，减少提示，让读者自己找证据。

## 实现与验收

复用现有页面入口和图形能力。独立小页可用原生 HTML 配合内联 SVG 或 Canvas。让概览和展开态共享对象标识、当前案例和布局坐标。对位置、尺寸和相连路径同步插值。连续点击展开和收回时，从当前画面反向过渡。窄屏可改变流向或分段显示，保留前后关系；键盘与触控可打开同一处细节。开启“减少动态效果”时直接呈现可比较的终态。

通过真实页面入口核对两件事：

1. **计算是否成立。** 用源码、手算或给定样例复核默认和变式的结果、首个差异及不变量，再复位确认基线。
2. **变化是否看得懂。** 观察概览、展开途中和展开后的画面，再点收回。必要时用慢放或连续帧检查：选中对象的位置能否追上、移动中的线头是否接在对象上、展开后能否同时看清相邻步骤和当前证据。窄屏和键盘下各走一遍核心操作。

交付可打开的页面和一个可立即尝试的动作。分别说明实际验证过的行为和仍需读者试用才能判断的教学效果。

制作类似 Transformer Explainer 的整页时，可先打开[可运行的原位展开示例](assets/cache-ttl.html)，对照展开、收回时的对象与连线。需要选择其他题材的图形或设计练习时，读[案例与设计来源](references/learning-patterns.md)。
